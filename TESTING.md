# Testing StatSnap

Three suites, one per package. None of them touch Atlas, Render, or The Odds
API: the backend runs against an in-memory MongoDB, the ETL against a
throwaway local `mongod`, and the one upstream HTTP call is stubbed at the
`fetch` boundary. A pull-request workflow (`.github/workflows/test.yml`) runs
all three; the production ETL cron in `etl.yml` is separate and unchanged.

## Run everything locally

```bash
cd frontend && npm test          # Vitest + React Testing Library (jsdom)
cd backend  && npm test          # Vitest + supertest + mongodb-memory-server
cd etl      && source venv/bin/activate && pip install -r requirements-dev.txt && python -m pytest
```

Coverage: `npm run test:coverage` in `frontend/` or `backend/`,
`python -m pytest --cov` in `etl/`. Reports print to the terminal; lcov/xml
files land in `coverage/` (git-ignored).

## What each suite is for

| Suite | Runs against | Highest-value tests |
|---|---|---|
| `frontend/src/utils/__tests__/stats.golden.test.js` | Golden JSON generated by Python | **The JS/Python contract.** Every season helper in `stats.js` must reproduce `percentiles.py` exactly, including null-means-no-basis. |
| `etl/tests/test_golden.py` | The same golden JSON | Fails if `percentiles.py` changes and the golden file was not regenerated. Together with the JS side this closes the loop in both directions. |
| `frontend/src/components/__tests__/AdvancedPanel.test.jsx` | Golden `positionConfigs` | Row order per position and the qualifier thresholds in the footnote must match what the ETL actually ranks. |
| `etl/tests/test_percentiles.py` | Synthetic weeks | Ratio-of-sums rules, zero and negative denominators, tiny samples, all-null weeks, tie handling, single-qualifier cohorts, qualifier gates, WR/TE separation. |
| `etl/tests/test_load.py` | Throwaway `mongod` | Bulk-upsert idempotency: same load twice is byte-identical, re-runs replace in place, `advanced` map is replaced not merged. Also pins the mid-season-trade behaviour (first-week team wins). |
| `backend/tests/*.routes.test.js` | mongodb-memory-server | Happy paths, 400/404, regex-metacharacter and word-boundary search, dedupe across seasons, the 10-row cap, projection allowlist, generic 500s. |
| `backend/tests/scheduleRefresh.test.js` | Stubbed `fetch` | Cold cache, stale cache, empty upstream, HTTP 5xx, network failure, unknown teams, unconfigured season, week rollover. None of them can damage a good cache. |
| `frontend/src/components/__tests__/*.test.jsx` | Mocked `utils/api.js` | Bio grid and loading/error/not-found states, GameLog DNP gap rows, Career ratio-of-sums totals, ScheduleRail degradation. |

## Expected failures (known bugs, deliberately pinned)

Some tests are declared with `it.fails`. They document a real, current
discrepancy; the suite stays green while the bug exists and turns red the
moment it is fixed, so the marker cannot silently outlive the bug.

- `stats.golden.test.js` `KNOWN_DRIFT`: currently empty. Add an entry only
  with a note explaining the discrepancy, and delete it with the fix.
- `players.routes.test.js`: `?q=a&q=b` (array query) returns 500 instead of
  400 because `q.trim()` runs before the try/catch.

## Regenerating the golden file

Whenever the aggregation contract in `etl/percentiles.py` changes:

```bash
cd etl && python generate_golden.py
```

Commit the regenerated `frontend/src/utils/__tests__/golden-season-aggregates.json`
with the change. Both `test_golden.py` and the Vitest suite will tell you if
you forget.

## Environment variables (all optional, tests only)

| Variable | Where | Purpose |
|---|---|---|
| `TEST_MONGO_URI` | ETL | Use an existing local MongoDB instead of spawning a temporary `mongod`. Must be `localhost`/`127.0.0.1`; Atlas/SRV URIs are refused. CI sets it to a `mongo:7` service container. |
| `MONGOMS_SYSTEM_BINARY` | Backend | Path to a `mongod` for mongodb-memory-server. Auto-detected from `PATH` if unset; otherwise a binary is downloaded once to `~/.cache/mongodb-binaries`. |
| `MONGOMS_DOWNLOAD_DIR` | Backend | Where that download goes. CI points it at a cached directory. |

`MONGO_URI` and `ODDS_API_KEY` are forced to harmless placeholder values by
the test setup files before any project module loads, so values in a local
`.env` can never reach a test run.

## Notes for whoever extends this

- Backend tests load project modules with `createRequire` rather than ESM
  `import`. The app requires its own files natively; importing the same file
  through Vitest's transform pipeline creates a second module instance and
  Mongoose throws `OverwriteModelError`. Keep everything on one graph.
- Prefer stubbing at boundaries (`fetch`, `utils/api.js`) over mocking
  internal modules. The tests should exercise the real client and controller
  code between the boundary and the assertion.
- Do not chase the coverage number. Add a test when a behaviour matters
  enough that you want to be told when it changes.
